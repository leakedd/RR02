## 2. Chaîne de lecture validée (LA chaîne critique)

```
GameAssembly.dylib base  →  ASLR via dyld_all_image_infos (.task info, TASK_DYLD_INFO)
klass = r64(g_base + 0x8d402f0)               → TypeInfo ListComponent<PlayerModel>
static_fields = r64(klass + 0xB8)
wrapper      = r64(static_fields + 0x8)       → instance 046885<T> (PoolList statique)
set          = r64(wrapper + 0x10)            → ListHashSet
count        = u32 @ set + 0x18
array        = r64(set + 0x10)
PlayerModel* = r64(array + 0x20 + 8*k)        → itération k = 0..count
pos Vector3  = float3 @ PlayerModel + 0x2F8   → (x, y, z) monde
```

- Validé live à 10Hz, 30–50 entrées, positions terrain cohérentes (y ≈ 1-17m), mouvement REAL joueurs détecté (18-25m / 5s = vitesse Rust).
- Base réelle Rust du jour : `0x131b98000` (SLIDE mémo à refaire à chaque relance jeu).

## 3. Détection du joueur LOCAL

**Pas trouvé via champ dédié** : `Batch player 0x375` est jamais `true` en RAM, aucun autre bool ne diffère entre joueurs.

**Solutions tentées** :
| Piste | Status |
|---|---|
| scanf klass `%b53757d1…_TypeInfo` @ VA `0x8d48400` | ❌ slot non initialisé RAM (obf `0x2001460f` zone non mappée) — le jeu n'appelle pas GetLocalPlayer au runtime courant |
| SteamID `PlayerModel + 0x2C0` | ❌ 0 partout (rempli côté serveur) |
| Bool publics de `BasePlayer+0x398 / 0x399` | tests sans résultat définitif |

**SOLUTION ACTUELLE (fonctionnelle, manuelle)** : dans l'overlay HTML — **track par position, pas par index**.
1. Tu **cliques ton point** sur la map → anchor mémorisé en {x,z}.
2. À chaque tick l'anchor snapne sur le joueur le plus proche (tolérance 15m).
3. Au respawn : tu re-cliques ta nouvelle position → 1 seconde, c'est fait.

Le spawn change l'index du pool (ton ancien was `#0`, ensuite `#19`) — en trackant par position on n'est pas dérangés par le renumérotage côté pool.
